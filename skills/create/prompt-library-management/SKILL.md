# Prompt library management

The prompt that made a perfect rain selfie in October is worth more than any model. A library keeps it: one file per
prompt, the exact identity block version, the model and settings, the refs, the score it earned, what it cost and the
hash of what it produced. When a model retires or her look gets a v2, you know exactly which prompts to migrate.

## When to use this

- A generation scored 7/7 — save it before you forget the settings.
- You need "the lounge sunglasses prompt" again, or a starting point for a new scene.
- A model is retiring or changed behaviour and you must find every prompt that uses it.
- The character's look changes (identity v1 → v2).
- Setting up prompts for a new character or a new agent.

## What you need

- A folder under version control (git) — prompts are text; diffs show exactly what changed.
- Node ≥ 20 for [scripts/index-prompts.mjs](scripts/index-prompts.mjs) (offline, no dependencies).
- The character bible and identity block ([../claudia-character-bible/SKILL.md](../claudia-character-bible/SKILL.md)).
- Read [references/schema.md](references/schema.md) for every front-matter field and the naming rules.

## Steps

### 1. Lay out the library

```text
prompts/
  README.md                      # what's here, who approves, current identity version
  _blocks/
    claudia-id-v1.md             # identity block, wardrobe strings, negative block (copied from the bible)
  claudia/
    p1-bedroom/   claudia.p1.room-vlog.md
    p2-club/      claudia.p2.dj-booth.md
    p3-lounge/    claudia.p3.lounge-sunglasses.md
    p4-city/      claudia.p4.rain-selfie.md
    p5-desk/      claudia.p5.desk-cat.md
    p6-travel/    claudia.p6.santorini.md · claudia.p6.airplane-window.md · claudia.p6.balcony-night.md
    banners/      claudia.banner.sunset-bed.md · claudia.banner.network.md · claudia.banner.collage.md
    studio/       claudia.studio.blue-portrait.md
  _ab/
    ab-log.csv                   # every A/B: what changed, scores, winner
  _retired/                      # prompts whose model is gone (kept for history)
index.csv                        # generated by scripts/index-prompts.mjs, never edited by hand
```

The 12 files in [examples/library/](examples/library/) are a complete starting set — copy them into `prompts/claudia/`.

### 2. One prompt = one file with front matter

```markdown
---
id: claudia.p4.rain-selfie
version: 1.1.0
status: approved
character: claudia
identity: CLAUDIA ID v1
pillar: P4
series: forecast-dared-me
scene: warehouse-rain
look: signature
kind: video
model: fal/kling-3-pro
fallback_models: [fal/kling-2.6-pro, google/omni-flash]
params: {aspect: "9:16", durationSec: 10, audio: true}
first_frame_model: google/nano-banana-2.1
refs: [01-front-neutral, 05-laugh, 09-phone-arm]
seed: none
cost_usd: 1.73
scores: {drift: 7, runs: 5, pass_rate: 0.8}
outputs:
  - {path: library/2026-10/mj_8B-1.mp4, sha256: 9a41c2e0}
tags: [ugc, selfie, rain, running, motion]
created: 2026-10-13
updated: 2026-10-13
retires: none
---
## First frame
[CLAUDIA ID v1] … (full text, never "see above")
## Prompt
…
## Notes
…
```

Rules: the body contains the **full** prompt text with the identity block pasted in (not a reference to it), so a file
is runnable on its own. Field details: [references/schema.md](references/schema.md). Blank file:
[templates/prompt-file.md](templates/prompt-file.md).

### 3. Name and tag consistently

- **id:** `<character>.<pillar or family>.<scene-slug>` — lowercase, dots between parts, hyphens inside a part.
  `claudia.p2.dj-booth`, `claudia.banner.network`, `mara.p1.night-train`.
- **Variants** of the same scene for a different model get a suffix: `claudia.p3.lounge-sunglasses.mj` (Midjourney),
  `.flux`, `.gpt`.
- **version:** semver. Patch = wording tweak that doesn't change the look (`1.0.1`); minor = new refs, lens, light or
  model params (`1.1.0`); major = new identity block version or different model family (`2.0.0`).
- **status:** `draft` → `approved` (scored ≥ 6/7 on ≥ 3 runs and a person signed off) → `deprecated` (still works,
  don't start new series with it) → `retired` (model gone; moved to `_retired/`).
- **tags:** format (`ugc`, `portrait`, `banner`, `carousel`, `loop`), setting words, motion words, special handling
  (`text-in-image`, `hands`, `crowd`).

### 4. Run a prompt from the library

Copy the body into the CLI or the batch manifest; never retype it.

```sh
claudia generate image "$(awk '/^## First frame/{f=1;next} /^## /{f=0} f' prompts/claudia/p4-city/claudia.p4.rain-selfie.md)" \
  --model google/nano-banana-2.1 --aspect 9:16 --resolution 2K \
  --ref refs/claudia/01-front-neutral.jpg,refs/claudia/09-phone-arm.jpg --max-usd 0.10 --dry-run
```

For a week of posts, reference prompts from [../batch-content-production/SKILL.md](../batch-content-production/SKILL.md)
manifests by `id` in each item's notes, so results can be scored back to the file.

### 5. Score and log every run

After each run, update the file: increment `scores.runs`, recompute `pass_rate` (share of runs scoring ≥ 6/7 on the drift
check in [../character-consistency/SKILL.md](../character-consistency/SKILL.md)), set `scores.drift` to the latest
best, append to `outputs` with the sha256 from the media sidecar (`output.sha256`). Commit with a message like
`claudia.p4.rain-selfie 1.1.0: 7/7 x2, kling-3-pro`.

### 6. A/B one variable at a time

Log every comparison in `_ab/ab-log.csv` ([templates/ab-log.csv](templates/ab-log.csv)):

```text
date,prompt_id,base_version,variable,a,b,runs_each,a_pass_rate,b_pass_rate,winner,notes
2026-10-14,claudia.p3.lounge-sunglasses,1.0.0,lens,35mm,50mm,4,0.50,0.75,b,50mm keeps the face adult; 35mm widened the jaw
```

Use a fixed `--seed` where the model honours it (FLUX, Midjourney) so only the variable changes. The winner becomes the
next minor version.

### 7. Version the identity block

When the owner changes her look (new streak colour, new cut), create `_blocks/claudia-id-v2.md`, never edit v1. Then:

1. New prompts use `[CLAUDIA ID v2]`; `identity: CLAUDIA ID v2`; bump them to the next major version.
2. Ongoing series keep v1 until a planned "new look" episode — audiences notice mid-series changes.
3. The indexer flags files whose `identity` and body tag disagree.

### 8. Deprecate before models disappear

Models retire on fixed dates (from `@useclaudia/media`, checked 2026-10):

| Date | What goes | Replacement |
|---|---|---|
| 2026-10-22 | Veo 3.1 previews (`google/veo-3.1`, `-fast`, `-lite`) | `google/omni-flash` |
| 2026-12-01 | GPT Image 1.5, GPT Image 1 Mini | `openai/gpt-image-2.5-flare` / `-sunburst` |
| 2026-12-31 | ElevenLabs premade voices | your own designed voice ids |
| 2027-01-06 | OpenAI `tts-1`, `tts-1-hd`, `gpt-4o-mini-tts` | `elevenlabs/v3` or `google/gemini-3.8-flash-tts` |
| retired | `google/imagen-4` (2026-08-17), `google/gemini-2.5-flash-image` | Nano Banana 2.1 / 2 |

```sh
node scripts/index-prompts.mjs prompts --warn-days 45      # flags prompts whose model retires within 45 days
```

```ts
const report = await media.checkModels();   // asks each provider which ids still exist (needs keys; dryRun: true to preview)
```

For each flagged prompt: copy to a `.v2` variant on the replacement model, re-run 3×, score, then set the old file's
`status: deprecated` and `retires: <date>`; after the date move it to `_retired/`.

### 9. Index the library

```sh
node scripts/index-prompts.mjs prompts > index.csv          # CSV for spreadsheets
node scripts/index-prompts.mjs prompts --json > index.json  # for agents
node scripts/index-prompts.mjs examples/library             # try it on the seed library
```

It reads every `.md` with front matter, writes one row per prompt, and prints warnings to stderr: duplicate ids, missing
required fields, body without the identity tag its `identity` field names, minor-coded words, and retiring models.
No network, no dependencies.

## Check before you finish

- [ ] Every saved prompt has id, version, status, model, params, identity, scores and the full prompt text in the body.
- [ ] The body's identity tag matches the `identity` field.
- [ ] Outputs recorded with sha256 from the media sidecar.
- [ ] Indexer runs clean (no duplicate ids, no missing fields); retiring-model warnings have a plan.
- [ ] No secrets, keys, private URLs or personal data in any prompt file.
- [ ] No prompt names or describes a real person, or asks for a minor-coded look.

## Pitfalls

- **"See identity block above."** Files that reference instead of include break when copied. Paste the block.
- **Editing approved prompts in place.** Bump the version; old outputs must still point at the text that made them.
- **One mega-prompt per scene for every model.** Models need different structures; make `.mj` / `.flux` variants.
- **Scores from one lucky run.** `approved` needs ≥ 3 runs; record `runs` and `pass_rate`, not just the best.
- **Library outside git.** You lose the history that explains why v1.2 works and v1.3 doesn't.
- **Ref names that change.** Name refs by pack number (`01-front-neutral`); never rename pack files.
